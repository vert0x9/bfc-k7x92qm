The base is solid. The site has the correct page language, allows pinch-zoom, has a skip-to-content link, and shows a visible focus ring in the header. The mobile menu, the FAQ accordions and the footer newsletter form are built correctly. The checkout passes, with correct labels and autofill on every field. The site has no accessibility overlay widget. This is good: overlays do not give legal protection and often cause new complaints.

Why this matters now

New York federal courts receive more ADA website claims than any other venue, and online stores are the most common target. These claims usually start with an automated scan of the homepage and product pages. The items in the action plan are the ones those scans find first. Each fix also makes the store easier to use for every customer: on mobile, with a keyboard, or in bright light.

One quick protective step: publish an accessibility statement with a contact email and phone number, and link it in the footer. The site does not have one today. A statement and a dated record of the fixes below show good-faith effort if a demand letter arrives.

This report is a technical audit. It is not legal advice.

Two terms used in this report

Contrast ratio

A number that shows how much text stands out from the color behind it. It goes from 1:1 (no difference, for example white on white) to 21:1 (black on white). Higher is easier to read. The standard asks for at least 4.5:1 for normal text. Below that, people with weak eyesight, older customers, and anyone reading a phone in sunlight can struggle to read it.

WCAG

The Web Content Accessibility Guidelines: the international rulebook for accessible websites. US courts and the Department of Justice use it to judge ADA website claims. Level AA is the usual target. The numbers in the WCAG column (for example 1.4.3) point to the exact rule, so a developer can look it up. You do not need them to read the report.

Where the work is

Header & navigation

Dropdown menus open on mouse hover only. Keyboard users cannot reach the submenu links.

Color contrast

The brand orange with white text, and some small grey text, do not stand out enough from their background to be easy to read.

Collection filters

Filter checkboxes and the sort menu are not announced by screen readers.

Cart drawer

The drawer opens, but keyboard focus stays behind it on the page.

Button & image labels

Some icon buttons, gallery dots and one hero image have no text alternative.

Checkout

Passes. Three minor items, all maintained by Shopify.

Recommended order of work

Ordered by the most risk removed per hour of work. Effort is an estimate for an experienced Shopify theme developer.

01

Adjust the brand orange for text and buttons

White text on the current orange has a contrast ratio of 3.2:1. The standard asks for 4.5:1 (see "Two terms used in this report" on the Summary tab). A slightly deeper orange (color code #b85409) reaches 4.9:1, keeps the brand look, and passes. Because the theme sets this color in one place, a single change fixes the Add to Cart button, prices, badges and the Rewards button on every page.

PriorityEffort: smallWCAG 1.4.3
02

Publish an accessibility statement

A short page with our commitment, the standard we work to (WCAG 2.2 AA), and an email and phone number for help. Link it in the footer.

PriorityEffort: small
03

Make the header menu work with a keyboard

Add a toggle to each top-level item that opens its dropdown with Enter or Space and announces its open or closed state. Today keyboard users cannot reach 69 of the 78 menu links.

PriorityEffort: mediumWCAG 2.1.1 · 4.1.2
04

Fix collection filter and search labels

The desktop filters share IDs with the hidden mobile filter panel, so each label points to the wrong checkbox. Make the IDs unique, and add labels to the sort menu and the search field.

PriorityEffort: small–mediumWCAG 1.3.1 · 4.1.2
05

Add names to icon buttons and fix image text

Give the product gallery dots and the Rewards button a name. Replace the raw code in the homepage hero image description with plain text. Add a description to the buy-back image. Keep one H1 heading on the homepage.

PriorityEffort: smallWCAG 1.1.1 · 4.1.2
06

Move focus into the cart drawer

When the drawer opens, move keyboard focus into it. When it closes, return focus to the cart icon.

PriorityEffort: smallWCAG 2.4.3
07

Add a pause button to the homepage carousel

The hero changes slide every 6 seconds. Add a visible pause button, or turn off autoplay.

PriorityEffort: smallWCAG 2.2.2
08

Second wave: contrast, states and small controls

Darken the light-grey small text, show the selected cosmetic grade to screen readers, make the star ratings readable, and enlarge the slider dots and swatches. See the full list in All findings.

ImprovementEffort: medium
09

Re-test and keep a dated log

Run the same scans after each release. A dated record of the improvements supports any response to a demand letter.

Ongoing
About accessibility apps: toolbar or overlay apps (accessiBe, UserWay and similar) do not change the theme code, so scanners still find the same items. In 2025 the FTC fined one of these vendors $1M for misleading compliance claims. The fixes above are the reliable route.

Clean-up

  • The Google merchant widget frame has no title.
  • The membership plan list on the homepage has invalid list markup.
  • The SX-70 banner link name does not include its visible text ("REC").
  • Two navigation areas have no unique name; some content sits outside page regions.
  • A few heading levels skip (footer "Newsletter", sell page "How it works").
  • Product gallery images repeat the product name. Add the view, for example "Pentax K1000, top plate".
  • Review the 21 outline: none rules in the theme CSS and confirm each one has a visible focus replacement.
  • One link opens a new tab without a warning.

Scope notes
